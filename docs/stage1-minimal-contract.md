## 1. 四个接口的边界（本文主线）

第一阶段**只定义四个接口**，其他一律不做。数据按接口方向流动（**这是技术链路，不是产品的业务关系**，见铁律 1）：

```text
网站（来源站点）──① 网站接入──▶ 平台（Python 适配器）──② 数据写入──▶ Java ──③ 列表／④ 详情──▶ Flutter
```

| # | 接口 | 方向 | 谁实现 | 位置 | 一句话边界 |
| --- | --- | --- | --- | --- | --- |
| ① | **网站接入接口** | 网站 → 平台 | Python 适配器（**只读**） | 第 4 节 | 只取作品元数据；不写网站、不碰用户数据、网站零改造 |
| ② | **数据写入接口** | Python → Java | Java | 第 5 节 | 按 `(source, source_id)` 幂等 upsert，字段缺失不覆盖 |
| ③ | **作品列表接口** | Flutter → Java | Java | 第 6.1 节 | 分页查询，**不返回 `summary`** |
| ④ | **作品详情接口** | Flutter → Java | Java | 第 6.2 节 | 按 `work_id` 取全字段，不存在返回 404 |

**三条铁律**

1. **通用客户端服务与来源站边界**

   平台面向多个独立运营的网站提供可复用的客户端能力，使各网站无需自行从零开发和维护完整客户端，即可通过平台为自己的用户提供更好的内容浏览、检索、收藏与跨端体验。平台服务的是来源网站及其用户，来源网站是独立的业务服务对象，而非单纯的数据供给方。

   - **数据边界**：平台通过约定的适配方式读取允许访问的公开作品数据，**不向来源网站回写作品业务数据**、**不代持来源网站的服务凭据**、不直接连接来源网站数据库、不抓取登录后内容。客户端不直接抓取来源网站数据，但可以在适当场景下打开来源网站原页。
     - **授权例外（2026-10-24 依定位新增）**：用户在来源站完成登录后，平台可持有**可撤销的用户令牌**，并可在该授权范围内读写**该用户本人**的收藏与观看状态。**授权的形态由站点决定**（含站点单方面授权、无用户同意页的形态；定位 §4.1：网站观点大于用户观点，但这不是用户不重要——是决定权排序）。**这不构成「代持来源站凭据」，也不构成「回写业务数据」**——判定依据是**授权关系（谁授权、能否撤销）**，不是凭据形态。
     - **仍然禁止**：平台代收用户密码再转发验证；平台持有来源站的管理员 / 服务凭据；平台代用户爬取登录后内容。
   - **多站边界**：平台复用通用技术能力，但不因此合并各来源网站的内容、用户体系或运营主体。每条作品数据均通过 `(source, source_id)` 确定来源身份，所有来源相关操作必须使用正确的来源上下文，不得将不同来源站的数据或功能错误混用。
   - **能力边界**：通用能力由平台统一实现，来源站之间的差异通过适配机制处理。平台只承诺当前阶段实际实现并在接口契约中定义的能力，不把产品愿景当成已交付功能。

   这里刻意不再使用「单向供给」或「网站 → 平台 → 客户端」作为产品关系定义。数据采集的方向仍然明确，但它只是技术链路，不是整个产品的业务关系。
2. **只碰作品元数据与本人数据，且本人身份优先来自来源站**：
   - **本人数据**（账号、会话、收藏、观看状态）可以进平台。
   - **身份归属（2026-10-24 依定位修正）**：来源网站已有用户时，**客户端应优先使用来源站身份**——用户在来源站登录，平台只持有可撤销令牌；**授权形态由站点决定**（定位 §4.2）。平台自建账号**仅是过渡方案**，用于来源站尚未开放授权端点的阶段，**不是产品终态**；采用过渡方案时必须**预先设计**向来源站身份切换的路径（账号映射与数据迁移），不能等切换时才想。
   - **禁止**：平台代收用户密码转发验证；**来源站的服务凭据、后台数据、以及未经授权的浏览历史与评论**，一律不进平台、不回取、不代持。
3. **来源是事实，平台是缓存**：网站不可用时保留上次快照，不用"抓不到"推断"已删除"。

**明确不做**：完整的 ACGN 数据库设计、多来源合并策略、系列与别名、封面本地化、**来源站的用户数据（浏览历史、评论、后台数据）与来源站的服务凭据**。平台自有的账号、会话、收藏与观看状态见铁律 2，不在此列；**来源站原生账号在用户本人授权下可作为客户端身份**（见铁律 2 与 §4.8），亦不在此列。

## 2. 最小字段集

### 2.1 作品字段（第一阶段就这些）

| 字段 | 类型 | 必填 | 谁产生 | 说明 |
| --- | --- | --- | --- | --- |
| `work_id` | string | 是 | **Java** | 平台内部标识。生成方式与取值格式由 Java 决定；**客户端只当不透明字符串处理**，不得解析其结构 |
| `work_type` | enum | 是 | Python 提交 | `anime` / `comic` / `game` / `novel` |
| `title` | string | 是 | Python 提交 | 来源标题原文，不做跨类型转换，不做清洗截断 |
| `summary` | string | **可空** | Python 提交 | `\r\n` 已统一为 `\n`；**不截断**（最长 7225 字），折叠由客户端处理 |
| `cover_url` | string | **可空** | **Java（代理 + 缓存）** | Python 提交来源地址；**由 Java 代理并本地缓存**，缓存未命中才按限流回源一次，之后由平台直接服务；客户端**绝不直连来源站**（小站，避免加压）。无封面时为 `null` |
| `release_year` | int | **可空** | Python 提交 | 来源站年份原值，实测非空率约 **95.9%**（2026-10-22 抽样复核，旧记录「98.5% 为空」已作废）。**缺失不是 0 年**，不得为缺失记录填 0；客户端遇 `null` 不渲染年份 |
| `tags` | string[] | **可空** | Python 提交 | 来源实测每条 0–4 个（源码 `[:5]` 截断存在但未触发）。站点空值是 `[]` 且无法区分"无标签/未录入"，适配器统一转 `null`，见 4.4.3 |
| `main_rating` | object | **可空** | Python 提交 | `{value, scale}`，`scale` **只接受 `0-10`**（openapi 的 `SourceRating.scale` 只有这一个枚举值）。其它尺度**整条 rejected**（`RATING_OUT_OF_SCALE`），须由来源适配器换算后提交——不能原样入库，否则 `sort=rating` 与 `min_rating` 会静默错位（W4 接 VNDB 实测，见 [`w4-second-site-report.md`](w4-second-site-report.md) §5）。**缺失不是 0 分** |
| `source` | string | 是 | Python 提交 | 来源标识，**取值不受限**（不设白名单）；当前库内有 `otaku_site` / `bangumi`。新增来源不需要改接口②③④（W4 已实测） |
| `source_id` | string | 是 | Python 提交 | 原站作品 id，字符串存储避免数值歧义 |
| `updated_at` | datetime | 是 | **Java 维护** | 记录最后更新时间 |
| `source_url` | string \| null | **可空** | **Python 来源适配器** | 对应来源站的作品原始页面地址，供客户端关联、展示或打开原页 |

**`source_url` 补充规则**

- 详情接口返回 `source_url`，列表接口保持精简结构（现为 7 字段，见第 6 节；2026-10-22 起含 `release_year`）。
- 优先采用来源站提供的真实原页地址；如果来源站未直接提供，只有在适配器能可靠确定详情页路径时才允许推导。
- 无法可靠确定时返回 `null`，不能通过猜测生成地址。
- 由客户端展示来源站入口并执行导航；客户端不自行拼接地址，也不通过这个字段抓取数据。
- 只允许打开来源站配置中可信的 HTTP/HTTPS 地址，避免将不可信 URL 当作来源站入口。
- `source_url` 缺失不应影响作品的其他功能。

> **兼容性决定**：当前阶段优先把它作为详情响应中的可空字段，不必为了增加该能力就立即增加数据库迁移。如果现有数据模型已经持久化来源原页地址，则复用；如果没有，则根据现有架构确定是由适配器计算，还是在后续确有持久化需求时增加字段。
>
> **当前状态（2026-10-22 更新）**：Otaku 站的**人读详情页路径已实测确认**为 `{base_url}/contents/{source_id}`——站点首页卡片链接即 `/contents/{id}`，且 `GET /contents/476` 返回 `200` 与 HTML 人读页（`<title>街角魔族 2丁目 · Otaku</title>`）。
>
> ⚠️ **注意区分两种地址**：接口地址 `/api/contents/{id}` 返回 **JSON**，**不得**用作客户端的回流入口（等于给用户一个无效链接）；回流入口必须使用**人读原页** `/contents/{id}`。适配器已按人读原页生成 `source_url`，接口②提交、详情接口返回、客户端展示回流入口均可正常落地。
>
> 一般规则不变：**无法可靠确定原页地址时返回 `null`，不通过猜测生成**。已能可靠确定原页的其他来源（如 Bangumi 的 `https://bgm.tv/subject/{id}`）同理。

**列表与详情的字段差别**

| 接口 | 返回字段 |
| --- | --- |
| ③ 列表 | `work_id`、`work_type`、`title`、`release_year`、`cover_url`、`tags`、`main_rating`（**7 个，不含 `summary`**） |
| ④ 详情 | 全部 12 个（含 `summary`、`source`、`source_id`、`updated_at`、`source_url`、`release_year`） |

### 2.2 第一阶段明确不纳入

| 字段 / 能力 | 不纳入的原因 |
| --- | --- |
| 系列 `series_id`、别名 `aliases`、原名 `title_original` | 来源库里有，但 **JSON API 未出口**。已向站主争取，争取到再纳入 |
| 话数 `episodes`、媒介 `media`、原作载体 `source_material` | 同上，且填充率未确认 |
| 多来源评分合并 | 第一阶段只有一个来源 |
| ~~封面下载到自有存储~~ | **已改为主张**：封面由 Java 代理 + 本地缓存（第 2.1 节），客户端不直连来源站 |
| 账号、收藏、观看状态 | 第二阶段范围，不在本契约 |

> **`release_year` 已移出本清单（2026-10-22）**：此前依据「约 98.5% 为空」判定不纳入，该统计**经复核是错的**——
> 实测 anime 均匀抽样 800 条非空 **95.9%**（另有独立抽查：page 1 非空 99.5%、page 30 非空 100%）。
> 现已在接口②与③④全链路纳入，见第 2.1 节与第 6 节。**仍然不得为缺失记录填 0**，`null` 就是 `null`。
>
> 落地细则：
> - **入库区间 `1900–2100`**，越界视为脏数据，该条整条 `rejected`（原因码 `INVALID_RELEASE_YEAR`）——不做静默截断或置 `null`；
> - **合并规则与其他可空字段一致**：本次 `null` 不覆盖已有值，值有变化才计入 `updated`；
> - 列表因此由 6 字段变 7 字段（第 6 节），仅新增字段，不影响唯一标识与已有字段语义。

### 2.3 可空规则（三条硬规则）

1. **必填只有四个**：`work_type`、`title`、`source`、`source_id`。缺任一，Java 应拒绝该条记录并返回字段级错误。
2. **可空的一律传 `null`，不传空字符串**。空字符串在入库前统一转 `null`。客户端遇到 `null` 必须走占位，不得显示 `0`、`"无"` 之类的伪值——尤其是评分。
3. **`tags` 有第三态**：`null` = 未提供（**不覆盖**已有值）；`[]` = 明确无标签（可据此清空）。**第一阶段只会出现 `null`**——`otaku_site` 的 `[]` 语义不清（实测 38.5% 为空，多为未录入），适配器统一转 `null`，见 4.4.3。三态保留在契约里，供后续能区分两种空值的站点使用。

## 3. 唯一标识

### 3.1 两层标识，各管一段

| 层 | 标识 | 谁用 | 说明 |
| --- | --- | --- | --- |
| 平台内部 | `work_id` | **客户端唯一使用** | Java 生成。客户端所有业务（收藏、状态、跳转详情）只认它 |
| 跨系统定位 | `(source, source_id)` | **Python 与 Java 之间** | 同步作业的定位依据，Java 侧建**唯一约束** |

`source_id` 可以返回给客户端做溯源展示，但**客户端不得用它做业务判断**。

### 3.2 判定链（Java 实现，就这么一条）

```
用 (source, source_id) 精确命中
  ├─ 命中 → 更新，不新增
  └─ 未命中 → 新增
```

**首期不做任何基于标题的模糊合并。** 实测约束摆在那里：anime 内重名 55 组（「铁臂阿童木」×3）、跨类型同名 341 组（「航海王」既是动画也是漫画）。按标题去重必然误合并。

### 3.3 客户端三条禁止

1. 不得用 `title` 判定两条记录是不是同一个作品。
2. 不得解析 `work_id` 的结构或自增规律。
3. 某次列表里没出现的作品，不代表已删除——**同步不做删除**（来源方也不承诺删除语义）。

## 4. 接口①：网站 → 平台（网站接入）

> 这一节回答两件事：**网站要以什么形式把已有数据交出来**，以及**平台伸手的边界停在哪**。
> 具体路径、参数名由各网站的适配器配置决定，本节只定接入规范。

### 4.1 接入边界

**平台会拿走的（仅作品元数据）**

| 数据 | 用途 | 必取 |
| --- | --- | --- |
| 站内作品 ID | 作为 `source_id`，跨系统唯一定位 | **必取** |
| 标题、类型 | 列表与详情展示 | **必取** |
| 简介 | 详情展示 | 可选 |
| 封面地址 | 列表与详情展示 | 可选 |
| 标签 | 列表筛选与展示 | 可选 |
| 评分（含尺度） | 详情展示 | 可选 |
| 来源更新时间 | 判断是否需更新 | 可选（拿不到就由平台自己记 `updated_at`） |

**平台绝不碰的**

| 数据 | 原因 |
| --- | --- |
| **用户密码** | **永不经平台**。登录在网站侧完成，平台只拿可撤销令牌（§4.8） |
| 收藏、观看状态 | 属用户本人数据：**经授权后可双向一致**；未授权时不回取网站（§4.8） |
| 浏览历史、点评 | 属用户个人数据，未经授权不回取网站 |
| 站内行为日志、后台管理数据、测试后台 | 与作品展示无关 |
| 网站数据库 | **平台不直连任何网站的数据库**，只走公开可读的接口或约定导出文件 |

**权限边界（硬约束）**

1. 平台对网站的**作品数据只读**：不 POST、不 PUT、不 DELETE、不反向同步（**用户本人在授权范围内的收藏 / 状态除外**，见铁律 1 授权例外与 §4.8）。
2. 只需"公开可读"级别的访问权限；需要密钥的接口一律不接，除非站主明确提供只读凭据。
3. 抓取范围限于作品列表与其字段，**不抓用户页面、不抓登录后的任何内容**。
4. 速率与配额由站主给定并写进适配器配置，超出即降速，不试探上限。
5. **身份授权（可选能力）**：若来源站提供授权端点，客户端登录在来源站完成，**用户密码不经过平台**，平台只持有可撤销的用户令牌；**授权形态（含是否设置用户同意页）由站点决定**。平台**不得**代收用户密码转发验证。

### 4.2 接入形态：拉优先，推为辅

| 形态 | 谁发起 | 适用场景 | 第一阶段 |
| --- | --- | --- | --- |
| **拉（pull）** | 平台 Python 适配器定时拉取 | 网站已有只读 JSON 接口 | **采用** |
| 推（push） | 网站主动把数据提交给平台 | 网站无公开接口，或数据只在库内 | 不采用，留待后续 |

第一阶段选**拉**，理由：Otaku 已有可用的只读 JSON 接口，采用拉模式**网站侧零改造**，也不必给平台开任何写权限——边界最小。

后续接入无接口的网站时，再定义推送接口（平台提供接收端点 + 接入密钥），但**数据格式复用本文第 2 节的字段集**，不另起一套。

### 4.3 网站需要提供的最小能力

一个网站要能被接入，至少满足这四项：

1. **可枚举作品**：能按类型分页返回作品列表，并给出总数（或可判断末页）。
2. **稳定的站内 ID**：同一作品每次返回的 ID 相同；**ID 不得回收给其他作品**（作品删除后 ID 作废，不重新分配）。
3. **必填三项非空**：ID、标题、类型。缺任一项的记录平台拒收并记日志，不猜测补齐。
4. **缺失字段要如实表达**：无简介就返回 `null` 或不返回该键，**不要返回 `""`、`0`、`"暂无"`**——伪值会一路传到客户端。

加分项（有则用，无则降级）：封面地址、标签数组、评分及尺度、存活检查端点。

### 4.4 平台侧的适配器配置

每个网站一份配置，**改配置不改代码**：

| 配置项 | 说明 |
| --- | --- |
| `source` | 接入方唯一标识，第一阶段固定 `otaku_site` |
| `base_url` | 站点地址。**封面等相对路径由它拼成绝对地址**，不硬编码 |
| 类型列表 | 该站点有哪些作品类型（`anime` / `comic` / `game` / `novel`） |
| 分页参数 | 该站的分页参数名与单页上限 |
| 限流参数 | 并发数、请求间隔、每日配额 |
| 字段映射 | 站点字段名 → 本文第 2 节字段名 |

#### 4.4.1 第一阶段 `otaku_site` 的实测参数

以下全部为 2026-10-20 03:10 对线上站点的只读实测，**适配器按此实现**；站点事实与风险明细见 [`旧站能力复用清单`](旧站能力复用清单)。

| 项 | 实测值 |
| --- | --- |
| 列表端点 | `GET {base_url}/api/contents?type={type}&page={page}&page_size={n}` |
| 类型取值 | `anime` / `comic` / `game` / `novel`，合计 12012（7894 / 1428 / 1464 / 1226） |
| `type` 省略 | 返回全类型（`total=12012`）。适配器**始终显式传 type**，不依赖该行为 |
| `type` 传错 | **`400`**。不是空数组、不是 404 → 适配器必须当**致命错误终止**，不能理解为「该类型没有作品」 |
| 分页上限 | `page_size` 硬上限 **500**（1000 → `422`）。站主要求 ≤200 是**限流口径**，按 200 用 |
| `page` 越界 | **`200` + `items: []`**，`total_pages` 照常返回 → 以 `items` 为空判定结束，不以 HTTP 状态判定 |
| 列表结构 | `{total, page, page_size, total_pages, items}` |
| 单条字段 | `id` `title` `type` `summary` `rating` `cover_url` `tags` `year` `bangumi_id`（9 个） |
| 详情 | `GET /api/contents/{id}`，结构与列表同构；不存在 → `404` + `{"detail":"内容不存在: id=N"}` |
| 标签词表 | `GET /api/tags?type=&limit=` → `{type, total, items:[{name,count}]}`；`limit` 上限 2000；**不传返回全部**（四类分别 197 / 118 / 130 / 104）；**`total` 是本次返回条数，不是词表总数** |
| 错误格式 | FastAPI 默认 `{"detail": ...}`：404 为字符串、422 为数组。**与本文第 7 节的 `{error:{...}}` 不同**，适配器分别解析，不套用平台信封 |
| 来源更新时间 | 站点**不提供** → `updated_at` 由平台在落库时记录 |
| 限流 | 并发 ≤2、1–2 req/s、每日 ≤5 万请求；封面下载单独 ≤2 并发 |

#### 4.4.2 字段对照（站点字段 → 平台字段）

| 站点字段 | 平台字段 | 实测形态 | 转换规则 |
| --- | --- | --- | --- |
| `id` | `source_id` | int | **转字符串**。不保留 int 语义——换站点后 `source_id` 可能不是数字 |
| `title` | `title` | str，非空 | 去首尾空白；清洗后为空则整条 `rejected` |
| `type` | `work_type` | 四值枚举 | 原样透传，不做映射 |
| `summary` | `summary` | str，最长 7225 字，含 `\r\n` 与全角空格 | 换行统一为 `\n`；**只在接口④出口**，接口③不返回 |
| `rating` | `main_rating` | **裸 float**（如 `8.7`），**站点不附带尺度** | 补平台常量尺度 `0-10` 与 `source`；`null` 不折算为 `0` |
| `cover_url` | `cover_url` | 相对路径 `/media/full/cover_{bangumi_id}.jpg` | 用配置的 `base_url` 拼绝对地址；空串视同 `null` |
| `tags` | `tags` | 数组，0–4 项；**空值是 `[]` 不是 `null`** | ⚠️ **`[]` 一律转为 `null`（未提供）**，理由见 4.4.3 |
| `year` | `release_year` | int 或 `null`，实测非空率约 95.9% | 原样透传；`null` 不填 0（2026-10-22 起纳入，见第 2.1 节） |
| `bangumi_id` | —— | int | 不入库。仅用于理解封面文件名，`cover_url` 已拼好，无需映射 |

**注意 `cover_url` 在三段上的含义不同**（同一个字段名，别混用）：

| 出现在 | 值是什么 | 谁产生 |
| --- | --- | --- |
| 接口① 站点返回体 | 站点相对路径，如 `/media/full/cover_265.jpg` | 站点 |
| 接口② Python → Java | 拼好的**来源站绝对地址**，如 `http://154.8.194.198:8000/media/full/cover_265.jpg` | Python |
| 接口③④ Java → 客户端 | **平台代理地址**（Java 回源后本地缓存再对外服务），客户端不直连来源站 | Java |

Java 在接口② 收到来源地址后自行下载/缓存，并在对外响应里换成自己的地址；**不得把来源站地址原样透给客户端**。

#### 4.4.3 为什么站点的 `[]` 要转成 `null`

第 2.3 节规定 `tags` 的 `null`（未提供，不覆盖）与 `[]`（明确无标签，可清空）语义不同。但这个站点**只有 `[]` 一种空值**，无法区分「这部作品确实没有标签」与「这条记录还没录入标签」——实测 anime 均匀抽样 1125 条中 38.5% 是 `[]`，多数属于后者。

若按字面把 `[]` 当「明确无标签」：
- 站点某次拉取异常返回空标签 → 平台会把已有标签全部清空，且**不可回滚**；
- 这是把站点的数据缺口误读成站点的明确声明。

因此 `otaku_site` 适配器把 `[]` 按「未提供」处理（转 `null`）。代价是站点侧真的删除标签时平台不会跟着清空——**宁可保留旧值，也不误删**，与 4.5 节第 2 条降级规则一致。

客户端展示不受影响：`null` 与 `[]` 都不渲染标签区，见 6.3 节。

后续若站点能区分两种空值（例如显式返回 `tags: []` 与 `tags: null`），适配器去掉这条转换即可，**契约本身不用改**。

### 4.5 网站变化时的三条降级规则

| 情况 | 平台行为 |
| --- | --- |
| 网站临时不可用 / 超时 | 保留上次成功快照，**不清空**；本次记失败，下次重试 |
| 某条记录某字段缺失 | 该字段**不覆盖**已有值（`null` 不覆盖），其余字段照常更新 |
| 网站改字段名 / 改路径 / 改分页语义 | 适配器**报错并停在该步**，不静默跳过、不把空结果当"作品全没了" |

### 4.6 多站点扩展边界（为后续阶段留的口子）

- 新增一个网站 = **加一份适配器配置 + 一个 `source` 取值**，不改第 2 节字段集、不改接口②③④。
- 跨站唯一键始终是 `(source, source_id)`；不同站点的相同 `source_id` 是**两个作品**。
- 同一作品在多个站点出现时，第一阶段**不做合并**（按标题合并必然误判，见第 3.2 节）。
- 第一阶段只接一个站点。多站点/租户适配（品牌、配置、接入规范）不在本契约范围。

### 4.7 来源站适配约定

每个来源的适配遵循以下规则，不另建复杂机制：

- 每个来源适配器负责识别来源、解析来源作品数据，并提供**可验证的原页地址**（`source_url`）。
- 不同来源的 URL 规则由**对应适配器维护**，不在客户端写死。
- 新来源必须能够正确区分**来源标识**（`source`）、**来源作品 ID**（`source_id`）和**原页地址**（`source_url`）。
- 暂时无法支持的来源能力可以留空，不要求为了统一接口而伪造数据。

这既支持 Otaku 首站接入，也为未来多站接入留出了空间。

### 4.8 身份接入约定（2026-10-24 依定位新增）

> 依据 `product-positioning.md` §4：**网站已有用户，客户端就该用网站的账号**。平台账号只是过渡。

| 项 | 约定 |
| --- | --- |
| 优先级 | 来源站身份 **>** 平台自建账号（过渡） |
| 授权方式 | 用户在来源站完成登录，平台只持**可撤销的用户令牌**。**授权的形态由站点决定**——含站点单方面授权、无用户同意页的形态（定位 §4.1：网站观点大于用户观点；红线不变：密码全程只在站点侧、平台永不经手） |
| 禁止 | 平台代收用户密码转发验证；平台持有来源站服务 / 管理员凭据 |
| 令牌要求 | 可撤销、可过期、作用域限定在「本人收藏与状态」 |
| 撤销入口归属 | 撤销能力在站点侧；**入口由站点决定**。首站 Otaku 定稿双形态（均已启用）：① **self-revoke**——持有效 Bearer 令牌的平台后端可撤销该令牌持有者名下、同一 client 的全部未吊销令牌（用户在客户端内点「断开与网站的连接」时触发；2026-10-24 负责人拍板启用）；② **管理员应急吊销**——站点管理员按 access_token 或 external_user_id 全量吊销。用户侧控制 = 客户端内退出登录时平台**即时本地解绑**（丢弃绑定、不再调用令牌）+「断开与网站的连接」时 self-revoke 远程吊销 + 经站点管理员应急吊销 |
| 未开放授权端点时 | 用平台自建账号过渡，并**预先设计**切换路径（账号映射、收藏迁移） |
| 本人数据读写 | 在用户授权范围内，客户端的收藏 / 状态可与来源站保持一致 |
| 多站 | 各站身份**互不打通**；同一用户在 A、B 两站是两个独立身份 |

**首站现状（Otaku）**：站点拥有完整账号体系（`/login`、`/register`、`/me`、`/contents/{id}/favorite`、`/contents/{id}/status` 等），但均为**网页表单 + 会话 cookie 的页面端点，无对外 JSON 接口、无 OAuth / token 签发端点**（2026-10-24 只读核验 `GET {base}/openapi.json`，共 131 个路径）。
**站主已确认将开放授权端点（2026-10-24 回复定稿契约）**：标准 OAuth 授权码——`GET /oauth/authorize`（浏览器重定向，白名单 + state）→ `POST /api/auth/token`（ticket + client_id + **client_secret**，服务端到服务端）→ `GET /api/me` → `POST /api/auth/revoke`（双形态：self-revoke 持 Bearer 自助吊销 + 站点管理员应急吊销，均已启用）。令牌 1 小时、scope 固定 `identity`（收藏 / 状态读写二期，需站点再次授权）。client_secret 按铁律存环境变量、绝不入库。详见 [`identity-auth-endpoint-playbook.md`](identity-auth-endpoint-playbook.md) §2。

## 5. 接口②：Python → Java（数据写入 / 同步）

> URL 路径、鉴权头名称、DTO 与代码组织**全部由 Java 负责人决定**。本文只定语义。

### 5.1 边界

- 只有 Python 同步作业调用，走内部令牌，**客户端不得持有该密钥**。
- 分批提交，建议单批 **≤ 500 条**。
- **只有 Java 写库**；Python 不直接碰数据库。

### 5.2 请求格式

```json
{
  "batch_id": "otaku_site-anime-20261020-3a9f1c",
  "source": "otaku_site",
  "items": [
    {
      "source_id": "476",
      "work_type": "anime",
      "title": "街角魔族 2丁目",
      "summary": "第一行\n第二行",
      "cover_url": "http://154.8.194.198:8000/media/full/cover_313852.jpg",
      "tags": ["日常", "搞笑"],
      "main_rating": { "value": 7.8, "scale": "0-10", "source": "otaku_site" }
    }
  ]
}
```

字段名与第 2.1 节、以及列表/详情出口**保持完全一致**（`main_rating` 不写成 `rating`），避免联调时两边对不上。
Java 侧 DTO 类名可自定，但 JSON 键名以本文为准。

`batch_id` = `{source}-{类型}-{日期}-{内容指纹}`，指纹为排序后 `source_id` 集合的哈希。
**同一批输入重跑得到同一个 `batch_id`**（已实测验证）。

### 5.3 响应格式

```json
{
  "batch_id": "otaku_site-anime-20261020-3a9f1c",
  "counts": { "inserted": 97, "updated": 3, "unchanged": 0, "rejected": 0 },
  "errors": [
    { "source_id": "9999", "code": "TITLE_REQUIRED", "message": "标题为空" }
  ]
}
```

逐条结果只需四类计数 + 失败明细。成功条目不必逐条回传。

### 5.4 幂等与重试

| 场景 | 期望行为 |
| --- | --- |
| 同一 `batch_id` 重跑 | **结果一致，不得重复入库**（验收 E1/E2） |
| 同一 `(source, source_id)` 重复提交 | 更新，不新增 |
| 网络错误 / 超时 / 5xx / 429 | Python **重试**（带退避） |
| 4xx（含 401、400） | **不重试**，直接记为未送达并落盘报告 |
| 缺内部令牌 | Python **提交前直接失败**，不发请求 |

### 5.5 创建与更新规则

> 「字段缺失不覆盖」是本契约的核心语义。网站常出现部分字段拉不到（简介 502、标签为空），不能因此把库里已有的好数据冲成 `null`。

| 场景 | 期望行为 |
| --- | --- |
| `(source, source_id)` 未命中 | **创建**。要求必填 4 项齐全，否则整条 `rejected`；可空字段缺失存 `null` |
| `(source, source_id)` 命中 | **更新**，只覆盖本次**出现且非 `null`** 的字段；未出现或为 `null` 的字段**保留原值** |
| 要清空 `tags` | 显式传 `[]`（`null` 不等于清空） |
| 必填字段缺失或为空 | 整条 `rejected`，**不创建、也不做部分更新** |
| `work_id` | **首次创建时生成，此后永不变**。标题、封面、评分变更都不换 `work_id`（验收 E2） |
| 同一批内 `source_id` 重复 | 按出现顺序处理，最后一次生效，并在响应的 `errors` 里给一条 `DUPLICATE_IN_BATCH` 提示 |
| 作品在来源侧消失 | **不删除**。第一阶段不处理删除语义，客户端仍可查到 |

字段级更新语义（与第 2.3 节一致）：`null` = 本次没数据，不覆盖；`[]` = 明确为空；有值 = 覆盖。

### 5.6 错误处理

见第 7 节统一格式。接口②额外约定：

- 单条记录校验失败 → 该条 `rejected`，**不影响同批其他记录**。
- 整批格式错误 → 整批拒绝，Python 记为未送达。
- 来源整次抓取异常 → Python **中止本次，不写入部分结果，不清空现有数据**。

## 6. 接口③④：Flutter → Java（列表与详情）

> URL 路径、DTO 命名、鉴权实现**由 Java 负责人决定**，本节只定语义、字段与响应形态。
> [`openapi.yaml`](openapi.yaml) 是本节请求与响应形状的机器可读版本；两者冲突时以本节为准。

**列表返回字段（固定）**：`work_id`、`work_type`、`title`、`release_year`、`cover_url`、`tags`、`main_rating`、`source`（共 8 个），另加分页字段 `total`、`page`、`page_size`、`total_pages`。**不返回** `summary`、`source_id`、`updated_at`、`source_url`——需要简介或回流入口请按 `work_id` 拉详情。

**详情返回字段（固定）**：第 2.1 节全部字段（含 `summary`、`source`、`source_id`、`updated_at`、`source_url`、`release_year`）。

### 6.1 作品列表

**请求参数**（名称由 Java 定，语义如下）：

| 参数 | 说明 |
| --- | --- |
| `type` | 可选，`anime`/`comic`/`game`/`novel`；不传 = 全部 |
| `q` | 可选，标题关键词模糊搜索 |
| `tag` | 可选，**标签精确匹配**（不模糊、不分词），可与 `type`/`q`/`sort` 组合；未知标签返回 `200` + 空数组而不是报错 |
| `sort` | 可选，排序方式：**`id`（默认，入库顺序升序）/ `rating`（评分高→低）/ `year`（年份新→旧）**；非法取值返回 `400`。三种排序都以 `id` 作次级键，**保证分页稳定**（同一查询多次顺序一致） |
| `min_rating` | 可选，榜单评分下限：只保留评分 **≥** 该值的作品，**无评分（`null`）一律排除**（`0` = 只要有过评分）。取值 `0`–`10`，非法值返回 `400`。与 `sort=rating` 的区别：`sort` 只把无评分沉底，`min_rating` 把它们移出结果集 |
| `page` / `page_size` | 分页，`page_size` 建议**上限 50** |

**响应**：

```json
{
  "total": 1200,
  "page": 1,
  "page_size": 20,
  "total_pages": 60,
  "items": [
    {
      "work_id": "...",
      "work_type": "anime",
      "title": "街角魔族 2丁目",
      "cover_url": "https://api.example.com/covers/W-8f3a91",
      "tags": ["日常", "搞笑"],
      "main_rating": { "value": 7.8, "scale": "0-10", "source": "otaku_site" }
    }
  ]
}
```

列表**不返回 `summary`**——最长 7225 字，会把列表响应撑爆。

**查询语义（避免两边理解不同）**

| 情况 | 约定 |
| --- | --- |
| 无匹配 / `q` 无结果 | `200` + `items: []` + `total: 0`，**不是 404** |
| `page` 超出 `total_pages` | `200` + `items: []`，前端据此显示"没有更多" |
| `page_size` 超过上限（50） | **按上限截断**，不报错（客户端不必自己裁剪） |
| `q` 匹配范围 | 只匹配 `title` 子串，忽略大小写；**不支持别名与拼音**（别名来源未出口，第一阶段做不到） |
| 空参数 | 全部可选，不传即"全部类型、无关键词、第 1 页" |

### 6.2 作品详情

按 `work_id` 取，返回第 2.1 节的**全部字段**：`work_id`、`work_type`、`title`、`summary`、`cover_url`、`tags`、`main_rating`、`source`、`source_id`、`updated_at`、`source_url`。

其中 `source_url` **可空**：无法可靠确定来源站原页地址时返回 `null`，不猜测生成。新增该字段**不改变**作品的唯一标识规则、列表接口结构或已有字段语义。

| 情况 | 响应 |
| --- | --- |
| 命中 | `200` + 作品对象（不再套一层 `data`，与列表 `items` 元素同构） |
| `work_id` 不存在 | `404` + `WORK_NOT_FOUND` |
| `work_id` 格式不像 ID（乱填、纯数字、超长） | **同样返回 `404`**，不返回 `400`——避免用错误码区分"存在与否" |

未找到时的响应体：

```json
{ "error": { "code": "WORK_NOT_FOUND", "message": "作品不存在" } }
```

客户端收到 `404` 后提示并返回列表，**不自动重试**。`work_id` 一律当不透明字符串，不解析、不做数值比较。

### 6.3 客户端展示约定

- `cover_url` 为 `null` → 显示占位图，不得用空白或报错占位。
- `main_rating` 为 `null` → **不显示评分**，不得显示 `0.0`。
- `summary` 为 `null` → 显示"暂无简介"；非 `null` 时按 `\n` 分段渲染。
- `tags` 为 `[]` → 不渲染标签区。

### 6.4 分页与排序

- 分页参数与响应字段名由 Java 定，`total` 必须返回，否则客户端无法判断末页。
- 排序：由 `sort` 指定，默认 `id`；`rating`（评分高→低）、`year`（年份新→旧）亦支持。三种排序都以 `id` 作次级键，**保证分页稳定**（同一查询多次返回顺序一致）。非法 `sort` 取值返回 `400`（`BAD_REQUEST`），与「查不到结果」区分开。

### 6.5 同标签推荐（详情页底部）

`GET /api/works/{work_id}/related`：按**共享标签**取若干相关作品，供详情页「相关内容推荐」渲染。

| 情况 | 响应 |
| --- | --- |
| 命中 | `200` + `{ "basis_tags": [...], "items": [WorkSummary...] }`（评分高→低，不含自身） |
| 作品不存在 / `work_id` 格式非法 | **404**（与详情一致） |
| 作品**没有标签** | `200` + `basis_tags: []` + `items: []`，不是 404、不是错误 |
| `limit` | 可选，省略为 6，超过 20 按 20 截断 |

- `basis_tags` 是**本次实际参与匹配的标签**（最多 5 个），客户端据此展示「同题材：科幻、机战」这类理由；为空表示该作品没有标签，此时 `items` 必为空。
- `items` 元素与列表 `items` **同构**（2026-10-24 起 8 字段 `WorkSummary`，新增的第 8 个是 `source`），复用同一个列表 DTO，不引入别的新字段。

## 7. 统一错误响应

接口②③④ 共用（接口① 是平台主动拉取，失败记在适配器日志，不走这个信封）：

```json
{ "error": { "code": "WORK_NOT_FOUND", "message": "作品不存在" } }
```

**第一阶段只需要这几个错误码**：

| code | HTTP | 含义 | 客户端/Python 该怎么做 |
| --- | --- | --- | --- |
| `UNAUTHORIZED` | 401 | 未认证或令牌无效 | **不重试**；Python 记为未送达 |
| `BAD_REQUEST` | 400 | 请求格式或参数错误 | **不重试**；修正后重发 |
| `WORK_NOT_FOUND` | 404 | 作品不存在（仅接口④） | 客户端提示后返回列表 |
| `BATCH_TOO_LARGE` | 413 | 单批条数超限 | Python 自动拆批后重发 |
| `RATE_LIMITED` | 429 | 限流 | **重试**，带退避 |
| `INTERNAL` | 500 | 服务端错误 | **重试**，带退避 |

接口②的逐条错误（如 `TITLE_REQUIRED`、`DUPLICATE_IN_BATCH`）走 5.3 节的 `errors` 数组，不进这个信封——一条坏记录不该拖垮整批。

>
> 实测补充（2026-10-20）：来源站 `/media/*` 与 `/covers/*` **均不带 `Access-Control-Allow-Origin`**，`Cache-Control` 仅约 43 分钟。前者意味着 Flutter Web 端直连必然跨域失败，后者意味着客户端拿不到长缓存——两条都独立支持"必须由平台代理"这个结论。

### 8.1 不由 Java 负责、但 Java 需要知道的

- **接口①由 Python 适配器实现**，Java 不接触来源站，也不需要来源站的任何凭据。
- 因此 Java 收到的数据**可能天生不完整**（简介缺失、标签为空、评分缺失），这是正常情况，不是 Python 的 bug——按第 2.3 节的 `null` 语义存即可，**不要用默认值填补**。
- 来源站限流与可用性由 Python 侧负责；Java 只需保证接口②本身能承受每秒 2 批以内的提交。
- **Java 代理封面时必须本地缓存**：缓存未命中才回源，且遵守来源站限流（封面下载 ≤2 并发、1–2 req/s）；不得让客户端直连来源站，避免给小站加压（见 [`旧站能力复用清单`](旧站能力复用清单)）。

## 9. 站点标识与客户端区分（第一阶段口径）

本节只写接口层的事实；网站接入的完整模型见 [`otaku-project-plan-v2.md`](otaku-project-plan-v2.md) 第 4 节。

- **站点标识**：数据用 `source` 标识站点，第一阶段固定为 `otaku_site`；`(source, source_id)` 在同一站点内唯一。
- **客户端归属（2026-10-24 依定位明确）**：客户端是**网站的客户端**——品牌、应用名、图标、用户体系均归属该接入网站，**平台只提供技术底座**。多站接入时每个站有各自的客户端与各自的用户，**互不打通**（见 `product-positioning.md` §3 边界 2、3）。
- **第一阶段客户端只服务 Otaku 单站点**：客户端通过构建/配置确定站点（Java 后端 base URL + 站点标识 + 品牌资源），**运行期不切换站点**；调用查询接口时**不需要传站点参数**。
- **列表/详情响应不返回站点选择字段**；`source` 只在详情中作为溯源信息返回，客户端**不得**用它做业务判断。
- **未来多站点**：每站一个 `source`；若确需“一个客户端多站点”，再引入 `site_id` 查询/响应维度与站点选择机制（待后续阶段，不在本契约）。
